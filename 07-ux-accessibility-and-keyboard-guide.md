# UX, Accessibility and Keyboard Guide

## User profile

Both users are owners aged 50+. Ease of use is a release requirement, not a cosmetic preference.

## Visual rules

- Base text around 16-18 px minimum on desktop.
- Important totals and status text larger.
- Large click/tap targets.
- High contrast between text, fields and background.
- Avoid light-grey text for important information.
- Use generous spacing.
- Do not overload screens with charts or tables.
- Do not rely on colour alone; show words like PAID, PARTIAL and PENDING.

## Interaction rules

- One main task per screen.
- The next action must be visually obvious.
- Use plain labels: `Receive Shipment`, `New Invoice`, `Receive Payment`, `Add Expense`.
- Avoid accounting jargon such as debtor settlement, GRN, journal posting or receivable allocation in normal UI.
- Never hide core actions inside three-dot menus.
- Show a review screen before irreversible posting.
- After posting, show exactly what happened.

Example: `Shipment received successfully. 2,480 Pcs added to stock.`

## Keyboard

- Tab: next field.
- Shift+Tab: previous field.
- Enter: choose selected search result / advance where safe.
- Esc: close search or go back to safe state.
- Article-number search receives focus first on product-entry rows.

## Validation

Never clear entered data after an error. Explain the problem in Hinglish and focus the incorrect field.

Example: `Quantity 0 nahi ho sakti. Dozen ya Pcs enter karein.`
